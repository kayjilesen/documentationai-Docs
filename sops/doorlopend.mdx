## Doel

Sites gezond houden zonder ad-hoc FTP of ongedocumenteerde uitzonderingen.

## Terugkerende taken

| Taak | Richtlijn |
|------|-----------|
| **Kleine wijzigingen** | Lokaal → Git → deploy staging (indien nodig) → productie; ACF Sync; cache purge |
| **Plugin/core updates** | Bij voorkeur eerst staging; daarna prod. Defender/security niet “even uit” |
| **Content voor klant** | Klant in WP; jij alleen bij pagebuilder/technisch |
| **Incidents** | Mail (Pushover), cache, cookies: eerst [Helpcentrum](/help-center), dan fix + docs |
| **Docs** | Leerpunten → SOP of Documentatie via Git |
| **Klantproject-dossier** | URL’s, uitzonderingen, speciale plugins actueel houden |

## Automatische updates (WPMU DEV Hub)

Sites onder beheer werk je niet met de hand bij. Hoe je een site aansluit, staat bij [WPMU DEV Hub](/wordpress/plugins/wpmu-dev-hub). In de Hub staat per site onder **Automate & Updates**:

| Instelling | Standaard | Waarom |
|------------|-----------|--------|
| Core, plugins en thema's | Automatisch bijwerken | Geen site met de hand bijwerken |
| Dagen | Maandag t/m donderdag | Gaat er iets stuk, dan is er nog tijd om het te herstellen terwijl iedereen werkt. Bij vrijdag of weekend zie je het pas maandag |
| Safe update check | Aan, op de belangrijkste pagina's (bijvoorbeeld Home en Contact) | Visuele controle na elke update. Kies pagina's met veel blokken en de pagina met het formulier |
| Back-up vooraf | Uit | xCloud maakt al dagelijks een [back-up](/hosting/backups) |
| Samenvatting per mail | Uit | Bij veel sites loopt je inbox vol met updates die toch goed gaan, en mis je de mail die er wel toe doet |
| Uptime-bewaking | Uit | Dat doet xCloud al op serverniveau |

<Callout kind="warning" title="Wat de controle niet ziet">
  De safe update check vergelijkt alleen hoe een pagina **eruitziet** voor en na de update. Een contactformulier dat daarna geen mail meer verstuurt, of een kapotte koppeling, ziet hij niet. Test na een update op een site met formulieren of een shop daarom altijd kort het formulier.
</Callout>

## Af (na elke productie-wijziging)

- [ ] Via Git/Deployer gegaan
- [ ] ACF Sync indien JSON gewijzigd
- [ ] Caches gepurged
- [ ] Steekproef op het gewijzigde onderdeel
- [ ] Uitzondering of nieuwe afspraak in docs/dossier gezet indien nodig
- [ ] Site onder de Hub: automatische updates volgens de standaard hierboven
